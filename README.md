# 我在使用的 AI Agent Skills

这是一份我个人整理的 AI Agent Skill 清单。

Skill 并不属于某一个特定的 Agent。它更像是一份可以复用的能力说明书，把触发条件、工作流程、工具使用规则和参考资料组织在一起。只要 Agent 能够读取并遵循这些说明，就可以根据各自的机制接入。

这些 Skill 主要覆盖前端设计、交互体验、中文写作、任务拆解、知识整理和日常效率工具。它们不代表完整的 Skill 生态，只是一些定位清晰、适合融入实际工作流的选择。

如果你也在使用支持 Skill 或自定义指令能力的 AI Agent，可以根据自己的工作内容挑选需要的部分，不必全部安装。

## 前端设计与工程

| Skill                  | 作用                                                   | 适用场景                                     |
| ---------------------- | ------------------------------------------------------ | -------------------------------------------- |
| `frontend-design`      | 设计并实现更有辨识度、更接近上线质量的前端界面         | 官网、后台系统、业务页面、仪表盘和视觉改版   |
| `interaction-design`   | 设计状态反馈、微交互、过渡效果和防呆体验               | 表单、弹窗、按钮反馈、异常状态和复杂操作流程 |
| `animation-vocabulary` | 把模糊的动效描述转换成可实现的动画术语和参数           | 不确定某种动画应该如何描述或实现时           |
| `review-animations`    | 检查动画节奏、性能、可访问性和体验问题                 | 动效完成后的代码评审与体验验收               |
| `karpathy-guidelines`  | 控制代码改动范围，减少过度设计、无效抽象和不必要复杂度 | 功能开发、代码修改、重构和问题修复           |
| [`ui-ux-pro-max`](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) | 提供可检索的 UI/UX 设计知识库并生成完整设计系统 | 页面设计、风格选型、配色、字体、图表和多技术栈实现 |

### 推荐组合

设计业务页面时，可以组合使用

```text
frontend-design
interaction-design
karpathy-guidelines
```

前两个负责视觉和交互质量，`karpathy-guidelines` 用来约束实现范围，避免为了追求效果引入过多复杂度。

处理页面动效时，可以组合使用

```text
animation-vocabulary
review-animations
```

先把动画意图表达清楚，再检查最终实现的节奏、性能和可访问性。

## 中文写作

| Skill            | 作用                                             | 适用场景                               |
| ---------------- | ------------------------------------------------ | -------------------------------------- |
| `blog-writer-cn` | 按中文技术博客的方法组织结构、案例和表达         | 技术教程、开发总结、项目复盘和知识分享 |
| `renwei-writing` | 润色中文内容，同时保留作者原本的语气和真实感     | 工作邮件、说明文档、个人文章和内容改写 |
| `khazix-writer`  | 用更有故事感、节奏感和卡兹克个人视角方式创作长文 | 工具分享、产品体验、方法论和公众号文章 |
| [`reply-marswan-comments`](skills/reply-marswan-comments) | 为「火星来信 Marswan」生成简短、贴题、有活人感的评论回复 | 公众号评论互动、读者提问、质疑和玩梗 |

### 如何选择

- 需要搭建完整的技术文章结构，使用 `blog-writer-cn`。

- 已经有初稿，希望文字更自然，使用 `renwei-writing`。

- 希望把工具或经历写成有叙事感的长文，使用 `khazix-writer`。

- 需要回复「火星来信 Marswan」公众号评论，使用 `reply-marswan-comments`。

## 任务分析与工作流

| Skill               | 作用                                                        | 适用场景                               |
| ------------------- | ----------------------------------------------------------- | -------------------------------------- |
| `leader`            | 把一句话想法拆成目标清晰、边界明确、可以验收的 Agent 任务书 | 复杂需求、长时间任务和多阶段开发工作   |
| `hv-analysis`       | 使用横向与纵向分析法拆解问题并形成结构化结论                | 方案比较、问题分析、业务研究和决策整理 |
| `find-skills`       | 根据当前需求寻找值得安装或复用的 Skill                      | 不确定现有 Skill 能否覆盖某项任务时    |
| `codex-auto-report` | 把自然语言需求整理成可执行的 Codex 定时报告任务             | 日报、周报、定期检查和信息监控         |
| `neat-freak`        | 在项目阶段结束时整理知识、文档、遗留事项和治理内容          | 功能收尾、版本发布、项目归档和知识沉淀 |

### 推荐工作流

一个相对完整的任务可以这样组织

```text
leader
具体领域 Skill
karpathy-guidelines
neat-freak
```

`leader` 负责把目标拆清楚，中间使用与任务相关的专业 Skill，开发过程中通过 `karpathy-guidelines` 控制复杂度，结束后再用 `neat-freak` 完成整理和收尾。

## 安装与接入

一个 Skill 通常是一个独立目录，核心入口是 `SKILL.md`。

```text
<skills-root>/<skill-name>/SKILL.md
```

不同 AI Agent 的加载方式和目录约定可能不同。可以把 Skill 放进对应 Agent 的用户级 Skill 目录，也可以通过插件、扩展或项目配置接入。

如果希望多个 Agent 共用一份 Skill，可以维护一个共享目录。

```text
~/.agents/skills/<skill-name>/SKILL.md
```

Codex 用户也可以使用自己的 Skill 目录。

```text
~/.codex/skills/<skill-name>/SKILL.md
```

`ui-ux-pro-max` 上游提供 Codex 专用安装器，会将核心 Skill 和配套设计 Skill 安装到 `~/.agents/skills/`：

```bash
npx ui-ux-pro-max-cli init --ai codex --global
```

这两个路径只是接入示例，不是 Skill 的平台限制。迁移到其他 Agent 时，按照对应产品的加载规则调整目录或导入方式即可。

一个完整的 Skill 还可能包含

```text
scripts/
references/
assets/
examples/
```

接入前建议先阅读 `SKILL.md`，确认它的触发条件、工具依赖和工作流程是否适合当前 Agent 与运行环境。

## 使用建议

- 根据任务选择 Skill，不要为了增加数量而安装。

- 为常用 Skill 准备自己的提示词模板和实际案例。

- 多个 Skill 组合时，为每个 Skill 分配清晰的职责。

- 定期检查不再适合当前工作流的 Skill。

- 分享第三方 Skill 时，保留原作者信息并遵守对应许可证。

Skill 的价值不在于装了多少，而在于能否在正确的任务中稳定发挥作用。
